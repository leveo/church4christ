# Learning Module Implementation Plan

> **Execution:** Use isolated worktrees, subagent-driven development,
> test-driven development, Workers best practices, and verification before
> completion. Every implementation task receives spec-compliance review before
> code-quality review.

**Goal:** Deliver a bilingual, provider-neutral Learning hub backed by Google
Classroom or an independently deployed Church4Christ Canvas derivative, with
secure provider connections, learner resources, assignment/quiz launch and state
reconciliation, privacy-bounded activity feedback, and explicit Instructure/AGPL
credit.

**Architecture:** Church4Christ stores bounded normalized metadata and activity;
Google Classroom or Canvas remains authoritative for content, files, submissions,
answers, comments, and grades. Provider adapters implement one validated contract.
Canvas remains a separate AGPL service and repository.

**Primary stack:** Astro 7 SSR, TypeScript 6, Cloudflare Workers, AppDb over D1
and PostgreSQL, Vitest Workers pool, Google Classroom REST API, Canvas REST API
and Live Events.

## Fixed decisions

- Branch/worktree: `codex/learning` at `.worktrees/learning`, based on current
  `origin/main`.
- Canvas checkout: `.worktrees/church4christ-canvas`, branch
  `codex/church4christ-learning`, never vendored into Church4Christ.
- First Church4Christ migration: `0017_learning.sql` in both migration trees.
- Learning supports D1 and PostgreSQL and belongs to Website + Community and Full
  Church presets.
- Provider choice is per program/course, not a mutually exclusive installation
  setting.
- Provider submission UI is authoritative; Church4Christ launches it and syncs
  the resulting state.
- No raw homework, quiz answers, comments, grades, Drive/Canvas file bytes, or
  clear-text provider credentials are persisted in the initial release.
- Activity Score uses submission/completion evidence only and is default disabled.

## Delivery rule

No task is complete until its focused tests have been observed RED for the intended
missing behavior, observed GREEN after implementation, spec review is approved,
quality review is approved, and the slice is committed. The overall goal remains
active until both providers, the learner experience, activity feedback, Canvas
credit/source obligations, operations, and full verification are all evidenced.
