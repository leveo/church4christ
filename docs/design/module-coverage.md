## Cross-module and core surfaces

- The public homepage, visit/about/beliefs/staff pages, giving invitation, sign-in/signup, profiles, privacy and custom-page output share the renewed public typography, imagery and page anatomy. Staff/detail pages can inherit the change through `ContentPage`, `StaffCard` or their renderer without needing a separate route rewrite.
- Public, member and admin shells retain module, role, area, resource and campus boundaries. The Sunday/admin workspace, `/admin/settings`, `/admin/navigation`, `/admin/campuses`, `/admin/onboarding`, reports and email operations are core/operational surfaces; they are not extra module keys beyond the 21 above.
- `MinistryWorkspace`, `CareWorkspace`, `ContentSurface`, `GatheringSurface` and `FinanceSurface` style their own workflows. The implementation includes matrices, ledgers, review queues, records, publishing editors and touch flows rather than relying solely on shared shell changes.
- Locale-free `/auth/[token]`, `/email-change/[token]` and invalid `/attendance/[token]` now use request `Accept-Language` negotiation through the existing `pickLocaleFromHeader` convention. Confirm/error title, body, button and retry link use one locale. Successful auth/email-change token consumption, cookies, redirects and notices are unchanged. Valid attendance still uses the verified owner’s language.
- `/respond/[token]` and `L/give/thanks` are confirmation/action utilities, not missing module bodies. The generic `404`, root redirect, signout, media/download/ICS routes, OAuth callbacks and webhooks do not need fabricated dashboards; their existing HTTP and security contracts remain the acceptance boundary.

## English presentation and source-content boundaries

English UI copy and custom block/navigation fallbacks must remain English. Chinese UI may use English when a Chinese value is absent. Bilingual administrative editor inputs, a person’s name, a message, and dedicated speaker/program/roster identity fields are intentional stored values and are not stripped or translated.

Existing single-language sermon and bulletin editorial data does not have complete language metadata. English eligibility currently uses a non-destructive Han-character heuristic on editorial content, with consistent latest/archive/direct lookup and an older-record fallback. A person’s name embedded inside an editorial paragraph can consequently make that whole editorial record ineligible. Dedicated person-name fields remain untouched. Explicit metadata is the future remedy; this visual batch introduces no migration or rewriting of existing user records. Prayer sheets and testimonies use their existing locale fields. Serving-plan raw titles/series and assignment IDs remain intact, with safe localized display fields for English views.

Shared packaged demonstration labels use English defaults where there is no locale-specific schema; independently localized English/Chinese collection and i18n rows remain. Demo visibility and first-run setup remain explicit. This is seed authoring, not a migration of user content.
